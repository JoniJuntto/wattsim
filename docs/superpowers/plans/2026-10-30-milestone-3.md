# wattsim milestone 3 plan: the rest of DESIGN.md

**Goal:** close every "In" item of DESIGN.md §2–3 that is not built yet: the CSMS simulator with conformance
checking (§2 CSMS row), security profiles 1–3 with the full certificate lifecycle and a built-in test CA (§3
Security), the MCP control surface (§3 Control surfaces), record/replay in the Open OCPP Trace Format with a
man-in-the-middle proxy (§2, §3 Recording), and vendor quirk profiles (§3 Vendor quirks).

**Global constraints** (as in milestones 1–2): Bun 1.4 workspaces; Biome (spaces, single quotes, width 120; `.tsx`
linted); TDD with `bun test`; every OCPP payload either side emits validates against the OCA schema of its version
(`validatePayload`); virtual clock injectable, no `Date.now()`/`setTimeout` outside `WallClock`; no new runtime
dependency without a line in DECISIONS.md (dated 2026-10-30) giving the reason; never edit files another wave-3
agent owns (below); never `git add/commit/stash/checkout` — the orchestrator commits; report the exact cross-package
change you need instead of making it. Each agent deletes the backlog lines it closes and documents user-facing
behaviour in README.md (its own section only) and, for DSL changes, docs/dsl.md.

## Wave A (parallel)

### A1 CSMS simulator — owns `packages/csms/**` (new)
- `startCsms(opts: { port?, host?, versions?: OcppVersion[], clock?, tls?: TlsServerOptions, basicAuth?: Record<identity,password>|((id,pw)=>boolean) })`
  → `Csms` with `url`, `stop()`, event emitter (`connected`, `disconnected`, `frame`, `violation`, `call`), and per
  connection `session(identity)`: `{ identity, version, call(action, payload): Promise<unknown>, respondWith(action, fn), state }`.
  Replace-quality successor to `packages/core/test/fake-csms.ts` (do not edit that file; the orchestrator migrates
  callers later).
- Default behaviour = a reasonable CSMS for every station-initiated action of 1.6, 2.0.1 and 2.1 (Boot Accepted with
  interval, Authorize Accepted unless the idToken is in a configured block list, StartTransaction assigns increasing
  ids, TransactionEvent accepted, DataTransfer UnknownVendorId, SignCertificate Accepted — the actual signing is A2's
  CA via an injectable `signer` hook, ...).
- **Conformance checker** (the point of this package): validate every inbound payload and every station reply to a
  CSMS CALL against the schema, plus state-machine legality per station, each finding a `ConformanceViolation`
  `{ identity, rule, severity: 'error'|'warning', message, specRef, frameId }` with `specRef` naming the spec
  section/requirement id (e.g. 2.0.1 `E01.FR.16`, 1.6 `§4.8`). Rules at minimum: any message before an accepted
  BootNotification (except Boot itself / when Pending: per B02/B03 rules), StatusNotification for unknown
  EVSE/connector or connectorId 0 status misuse, transaction events out of order (Updated/Ended without Started,
  seqNo gaps/duplicates per E-section, Started twice), meter register going backwards within a transaction,
  StopTransaction for unknown id, timestamps far in the future/past (> 5 min skew), Heartbeat far more often than the
  interval, CALL while another CALL from the same station awaits an answer (OCPP-J one-in-flight), CALLRESULT for an
  unknown id, message id reuse. Each rule unit-tested with a positive and a negative case; an end-to-end test drives
  real `@wattsim/core` Stations (1.6, 2.0.1, 2.1) through full sessions and asserts zero violations.
- CLI-free in this wave; export a `report()` summary (counts per rule, per identity).

### A2 PKI and security profiles — owns `packages/pki/**` (new), `packages/core/src/{connection,station}.ts`
  (security/TLS/certificate parts only), `packages/core/src/adapters/**` (certificate & security messages only),
  `packages/core/src/security.ts` (new), core tests for these
- `packages/pki`: a test CA: `createTestCa({ name?, validityDays? })` → root (+ optional sub-CA) with PEMs;
  `issueServerCert(ca, hosts)`, `issueClientCert(ca, identity)`, `signCsr(ca, csrPem, { identity? })`,
  `createCsr(keyPair, { commonName, organization })`, `fingerprint/hashData (issuerNameHash, issuerKeyHash,
  serialNumber per OCPP CertificateHashDataType, sha256)`. Real X.509: use `@peculiar/x509` (+ WebCrypto) unless
  Bun's built-ins suffice — check first; record the choice in DECISIONS.md. Keys ECDSA P-256 by default, RSA option.
- Station security profiles: 1 = basic auth over ws (exists); 2 = TLS (wss) + basic auth, server cert verified against
  configured CA; 3 = TLS with client certificate (mTLS). Station config `security?: { profile: 1|2|3, ca?: string,
  clientCert?: string, clientKey?: string }`. Verify Bun's WebSocket client TLS options (`tls: { ca, cert, key }`) in
  this Bun version and test against a local `Bun.serve` TLS endpoint with a cert from the test CA.
- Certificate lifecycle on the station: 2.0.1/2.1 `SignCertificate` with a real CSR (key generated per station),
  `CertificateSigned` installs the chain (verify it chains to the CA and matches the key; reject otherwise),
  `InstallCertificate`, `DeleteCertificate`, `GetInstalledCertificateIds`, `Get15118EVCertificate` (return a canned
  EXI string / `Failed` with reason — no real ISO 15118), `GetCertificateStatus` (OCSP: answer from the CA's own
  status table, no network), `SecurityEventNotification` for the events the station can actually produce
  (StartupOfTheDevice, ResetOrReboot, InvalidCsmsCertificate, SettingSystemTime, ...); `TriggerMessage`
  `SignChargingStationCertificate`. 1.6: the Security Whitepaper equivalents (`SignCertificate`, `CertificateSigned`,
  `InstallCertificate`, `DeleteCertificate`, `GetInstalledCertificateIds`, `SecurityEventNotification`,
  `ExtendedTriggerMessage`, `SignedUpdateFirmware`/`SignedFirmwareStatusNotification` if the vendored v16 schemas
  contain them — check `packages/protocol/schemas/v16`; if they are absent, implement them as DataTransfer-free
  payload builders validated by a hand-written schema in core and note it in DECISIONS.md).
- `SetNetworkProfile` (2.x) / `SecurityProfile` config key (1.6): accept upgrades, reconnect with the new profile,
  never downgrade (spec A05/A06/A07 rules).
- Tests drive a TLS `Bun.serve` CSMS (from a small test helper; do not depend on A1's package, it is being written in
  parallel) for profiles 2 and 3, including a wrong-CA failure, plus the full CSR → CertificateSigned round trip.

### A3 MCP server — owns `packages/mcp/**` (new), `packages/cli/src/commands/mcp.ts` (new file only)
- An MCP server (stdio transport, `@modelcontextprotocol/sdk`, pinned exact version; use context7 for the current
  API) exposing wattsim to agents. It embeds the UI server's registry by calling `startServer` from
  `@wattsim/server` on a free local port (or `--attach http://host:port` to an already running `wattsim ui`), so a
  person watching the UI sees what the agent does. Tools are thin wrappers over the HTTP contract in
  docs/superpowers/plans/2026-10-30-ui.md: `list_stations`, `create_station`, `delete_station`, `station_action`,
  `add_chaos_rule`, `remove_chaos_rule`, `get_frames` (with filters), `validate_payload`, `start_test_csms`,
  `export_session`, plus scenario tools that need no server: `check_scenario` (text → ok / errors with line:col),
  `format_scenario`, `run_scenario` (text, csmsUrl?, virtual default true, seed → per-station results, asserts,
  violations; uses `@wattsim/scenario` `run`). Good tool descriptions and zod input schemas; resources:
  `wattsim://docs/dsl` (docs/dsl.md), `wattsim://stations/{id}` (StationView JSON).
- `wattsim mcp [--attach url]` command (the orchestrator registers it in cli index.ts and adds the dependency).
- Tests: drive the server in-process with the SDK's in-memory transport pair: create station on the test CSMS, plug,
  start, read frames, export; scenario tools on examples/basic.ws.
- README section "Use it from an AI agent" with the `claude mcp add` / generic MCP config snippet.

### A4 Record/replay and proxy — owns `packages/trace/**` (new), `packages/cli/src/commands/{proxy,replay}.ts` (new)
- Research the **Open OCPP Trace Format** (DESIGN.md §3; Apache-2.0 schema, JSON/JSONL) — find its spec/schema
  online (WebSearch/WebFetch), vendor the schema with its license notice under `packages/trace/schemas/`, and
  implement reader/writer + validation against it. If the format cannot be found or is not usable, stop and report
  what you found before inventing anything.
- Import path for plain JSONL-of-frames (`{ts, dir, identity, frame}` per line; accept a raw `[2, ...]` frame per line
  too).
- Recording: a `Recorder` that attaches to a core `Station` (its `frame` events) or to the proxy and writes the trace.
- **Proxy (MITM)**: `startProxy({ listen, upstream, record?: path, chaos?: ChaosEngine })` — accepts a charger's
  WebSocket (negotiating the subprotocol it offers), opens the same identity/subprotocol to the upstream CSMS,
  forwards frames both ways, records them, and can apply core `ChaosEngine` rules (delay, drop, corrupt, ...) per
  direction. Basic-auth header passthrough. (TLS termination later via A2's options: accept `tls` options but test
  plain ws only.)
- Replay: `replay(trace, { csmsUrl, speed | virtual, identityMap? })` replays the station side of a recorded trace
  against a CSMS (the CSMS-side frames become expectations; mismatches reported with frame index), and
  `wattsim replay <trace> [--csms url] [--speed n]`; `wattsim proxy --listen 9000 --upstream ws://... --record
  out.jsonl [--chaos "drop out MeterValues nth 3"]` (the orchestrator registers the commands).
- Also `trace → .ws` conversion (`toScenario(trace)`): station-initiated actions become DSL statements where a
  primitive exists, otherwise `send`; CSMS replies become `expect result`. Output must pass `wattsim check`.
- Tests: proxy between a core Station and FakeCsms (import `packages/core/test/fake-csms.ts` by relative path),
  recording round trip, replay against FakeCsms, JSONL import, toScenario output parses.

## Wave B (after A merges)

### B1 Vendor quirk profiles — owns `packages/scenario/**` (quirk loading), `quirks/` (examples dir), core hooks it needs
- A quirk profile is a named bundle of config overrides + fault rules written in scenario primitives, contributable
  without code (DESIGN.md §3): a `.ws` fragment `quirk "name" { ... }` with station-block statements (config, chaos,
  on-replies), applied with `use quirk "name"` / `--quirk file`. Plugin hook for code-level quirks: a TS module
  exporting `(station: Station) => void`. Ships generic example profiles only (no named vendors): e.g.
  `slow-boot`, `lossy-meter`, `chatty-heartbeat`, `ignores-remote-stop`. Record-to-quirk: `wattsim quirk derive
  <trace>` diffs a recorded trace against spec-strict behaviour and emits a draft profile (A4 + A1's checker).
