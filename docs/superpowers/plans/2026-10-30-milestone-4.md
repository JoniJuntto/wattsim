# wattsim milestone 4 plan: realism, full fault catalogue, tooling, server mode, scale

**Goal:** close the remaining DESIGN.md scope after milestone 3: §2 EV row and §3 Realism, the full §3 fault
catalogue, §4 tooling (VS Code extension, browser editor, docs), §5 server-mode persistence, Docker, a CSMS view in
the UI, and the §3 Scale target (~10k idle stations per process, horizontal scale by id ranges).

**Global constraints** (as before): Bun 1.4 workspaces; Biome; TDD with `bun test`; every OCPP payload either side
emits validates against its version's schema; virtual clock only; no runtime dependency without a DECISIONS.md line
(dated 2026-10-30); never edit files another milestone-4 agent owns; never `git add/commit/stash/checkout`; report the
exact cross-package change you need instead of making it. The four packages core, scenario, server and ui are each
owned by exactly one agent in a given wave (below). Update README (your section) and docs/dsl.md for DSL changes.

## Wave 4a (parallel)

### R: Realism — owns `packages/core/src/{ev,meter}.ts`, new `packages/core/src/{ocmf,tariff,phases}.ts`, the 2.1/2.0.1 tariff, cost, V2X and ISO 15118 message handling in `packages/core/src/adapters/**`, `packages/core/src/station.ts` (EV/meter/limit parts), core tests
- EV: temperature derating (battery temp model, ambient config, curve × derate), cable rating (`cableMaxA` caps current), phase
  switching (1↔3 when the schedule period says `numberPhases`, or the EV supports only 1), V2X discharge for 2.1
  (negative limits / discharge setpoints → negative power, meter Export register), ISO 15118 behaviours: EV-requested
  suspend/resume, `NotifyEVChargingNeeds` (2.x) with departure time and energy request, Plug & Charge authorization
  (Authorize with `iso15118CertificateHashData` / contract certificate from the V2G chain installed in milestone 3).
- Meter: OCMF-signed readings (OCMF format per S.A.F.E. spec: `OCMF|{payload}|{signature}`, ECDSA secp256r1 with a
  per-station key) as `signedMeterValue` (2.x `SignedMeterValueType`) / 1.6 `SignedData` format; a constant-power trivial
  model (`meterModel: 'constant'`) for load runs; `EvModel`/`MeterModel` pluggable via StationConfig factories.
- Tariffs/cost (2.1, and 2.0.1 CostUpdated / California Pricing where schemas allow): `SetDefaultTariff`,
  `ChangeTransactionTariff`, `GetTariffs`, `ClearTariffs`, running cost in TransactionEvent `costDetails`
  (2.1) computed from the tariff's energy/time/fixed elements with restrictions (time of day, weekday, kWh, duration)
  evaluated on the virtual clock, including across midnight and DST (use the tariff's time zone).
- Scenario access: new EV props are generic `ev plug ... { name value }` props — report the prop names/units you add;
  the D agent wires them in the interpreter (you do not edit packages/scenario).

### F: Full fault catalogue — owns `packages/core/src/{chaos,connection}.ts`, new `packages/core/src/faults.ts`, `packages/scenario/**`, `docs/dsl.md`, core chaos/connection tests
- Transport: `jitter` (random delay in a range, seeded), `reorder` (hold a frame and release after the next N),
  `halfOpen` (stop reading/writing without closing; the CSMS sees silence), `slowRead` (deliver inbound frames with
  a per-frame delay that grows), `reconnectStorm` (drop and reconnect K times in T).
- Protocol (outbound mutations, all deliberate schema breaks reported as chaos, not as violations of wattsim):
  `invalidEnum` (replace an enum value), `missingField` (drop a required field), `timestamp ±dur` (shift
  timestamps), `oversized N kB` (pad a payload). Name the path when needed (`missingField idTag`).
- Behavioural, as DSL statements on top of core: `bootLoop n` (reboot right after Accepted n times), `fault evse N
  [errorCode]` (spontaneous Faulted with the 1.6 error code / 2.x connector status + NotifyEvent where the version
  has it), `meter backwards Wh` / `meter reset` (a deliberate register jump), `reset hard|soft` mid-transaction,
  `net drop dur duplicate` (offline queue replayed with duplicate message ids on reconnect).
- Parser + formatter + interpreter + docs for all of it, plus wiring R's new EV props (R reports them; message R's
  agent is not possible — read `packages/core/src/ev.ts` as it lands and wire generically: unknown props pass through
  to the EV config with their unit). Tests for each fault against FakeCsms or `@wattsim/csms` (the CSMS checker must
  flag the protocol faults with the expected rule — use it as the oracle).

### T1: VS Code extension and language server — owns new `packages/vscode/**`, new `packages/lsp/**`
- `packages/lsp`: a Language Server (vscode-languageserver over stdio) built on `@wattsim/scenario`: diagnostics
  from `parse` (line:col → range) and from `link` (quirk/import errors), formatting via `format`, hover docs for
  keywords/actions (action names from `@wattsim/protocol` per the file's `version`), completion for keywords,
  OCPP actions and quirk names, go-to-definition for `call proc`, `use quirk`, `import`. Unit tests drive the server
  with an in-memory connection.
- `packages/vscode`: the extension (language id `wattsim`, `.ws` files), a TextMate grammar generated from the
  lexer's keyword list by a script (DESIGN §4: one grammar source), snippets, the LSP client, and `vsce package`
  producing a `.vsix` in CI artifacts (no publishing). Grammar test: tokenise every examples/*.ws and quirks/*.ws with
  `vscode-textmate` + `vscode-oniguruma` and assert no unknown tokens on keywords.

### T2: Docs site — owns new `packages/docs/**`, `.github/workflows/docs.yml`
- Fumadocs (DESIGN §5) static export: Getting started, the DSL reference (generated from docs/dsl.md, single source),
  CLI reference (generated from citty command metadata by a script), UI tour with screenshots you take of `wattsim
  ui --` on mock data, MCP, CSMS simulator + conformance rule table (generated from `@wattsim/csms` RULES), security
  & certificates, record/replay/proxy, quirks, library API overview. Build must be static (`next build` with
  `output: 'export'` or Fumadocs' static mode) and run in CI; GitHub Pages deploy workflow gated to `main` (written,
  not enabled — no secrets). Check current Fumadocs setup with context7.

### P: Server mode — owns `packages/server/**`, `packages/ui/**`, new `Dockerfile`, `.dockerignore`, `docker/**`
- Persistence (`bun:sqlite` + Drizzle, DESIGN §5), server mode only: run history (scenario runs started from the UI
  with results/asserts/violations), saved scenarios, recordings (the session frames as Open OCPP Trace via
  `@wattsim/trace`), CSMS conformance reports; `--data <dir>` (default `~/.wattsim`), migrations committed.
- UI: (1) a **Scenarios** page with a browser `.ws` editor (CodeMirror 6 with a wattsim language mode built from the
  scenario lexer's keyword list; live diagnostics via a new `POST /api/scenario/check`; format button) that runs a
  scenario (virtual or real time) against the test CSMS or a URL and shows per-station results; run history list.
  (2) a **CSMS** page: sessions connected to the built-in test CSMS, its conformance findings live (rule, severity,
  specRef, station, frame link), and a report export (JSON/JUnit). Server streams CSMS events over the existing
  `/api/stream` (new message types, documented in the UI contract doc). (3) Recordings: download the session as an
  `.oot.jsonl` trace.
- Docker: multi-stage image (`oven/bun` pinned), builds the UI, runs `wattsim ui --host 0.0.0.0 --no-open
  --data /data`, healthcheck on `/api/health`, non-root user; `docker build` in CI (no push).
- Verify in the browser yourself (preview tools; `.claude/launch.json` has `wattsim-ui` and `ui-dev`).
