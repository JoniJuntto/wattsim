# wattsim DLM test environment plan

**Goal:** a development and test environment for **dynamic load management** (DLM): an electrical model of a site
(grid connection, transformer, main fuse, distribution boards, sub-boards, circuits, protective devices, cables,
phase rotation) carrying wattsim's simulated chargers plus non-EV loads, so a DLM controller under test, whether it
lives in a CSMS (OCPP smart charging) or in a local controller (reading meters over Modbus TCP), meets realistic
measurements, and so overloads, fuse and breaker trips and unfair or wasteful allocation are visible, asserted and
scored.

Decisions taken (user asked for the full environment; defaults chosen, change on request):
- The DLM under test is **external**: the user's CSMS (via `SetChargingProfile` / 2.x external constraints) and/or a
  local controller reading emulated meters. wattsim also ships a simple **reference DLM** (phase-aware fair share) as
  a baseline to compare against, never as the thing being tested.
- Measurements are offered where real controllers read them: **Modbus TCP meters** with real public register maps
  (Eastron SDM630, Carlo Gavazzi EM24, plus a documented generic map), OCPP MeterValues per phase from the stations
  (exists), Prometheus, and the UI/HTTP/WebSocket API.
- Electrical model is quasi-static per phase (no power-flow solver): currents add up the tree per phase, voltage drop
  from cable impedance, protective devices integrate their time-current curves on the virtual clock.

## Model (`packages/grid`, pure, no I/O)

- **Topology:** a tree. `Site { supply }` → `Node`s. Node kinds: `transformer` (kVA, impedance %), `fuse` (gG/aM, In),
  `breaker` (MCB/MCCB/RCBO, curve B/C/D/K/Z or adjustable Ir/Isd, In, poles), `board` (distribution board/sub-board,
  rating), `cable` (cross-section mm², material Cu/Al, length m, installation method → ampacity per IEC 60364-5-52
  table subset, R/X per km), `meter` (CT/meter point, maps to Modbus device), and leaves: `evse` (a wattsim station
  EVSE with **phase mapping/rotation** e.g. L2L3L1, 1- or 3-phase), `load` (base/building load: constant, profile
  from CSV time series or daily/weekly shape, per-phase split, power factor), `pv` (generation profile, negative),
  `battery` (stationary storage with its own setpoint, may be controlled by the DLM too), `heatpump`/generic step load.
- **Phases:** L1/L2/L3/N; single-phase loads on a named phase; neutral current from imbalance; per-phase currents and
  power, cos φ.
- **Protection:** time-current curves: MCB B/C/D per IEC 60898-1 (thermal band 1.13–1.45 In, magnetic 3–5/5–10/10–20 In),
  gG fuses per IEC 60269 (conventional non-fusing/fusing currents and a pre-arcing curve approximation), MCCB with
  Ir/tr/Isd/Ii. Thermal memory (I²t integration with cooling), deterministic trip at the curve's median, optional
  seeded tolerance band. Trip → downstream de-energised; reclose manual (API/DSL) or automatic after a delay.
  Selectivity check (upstream device must not trip before downstream) as a static analysis warning.
- **Limits & violations:** per node: current above rating (any phase), cable over ampacity, transformer overload,
  voltage outside EN 50160 band (±10 %), phase imbalance above a threshold (e.g. 16 A / 20 A asymmetry rule as
  configurable), neutral overload. Each with start/end time, peak, duration, integral (A·s over limit).
- **Evaluation:** `site.evaluate(t)` given current per leaf per phase → node currents, voltages, device thermal state,
  trips; `nextEvent(t)` returns the earliest time a device would trip at current loads (so the virtual clock can stop
  exactly there, no polling).

## Integration (after the milestone-4 fixes land)

- **core:** a station/EVSE can be **supplied** by a grid leaf: available phases and voltage come from the site; a
  trip upstream = power loss (station drops off OCPP, EVSEs go Unavailable/Faulted per version semantics, EV stops;
  on reclose the station boots with `PowerUp`). Station draw per phase (with rotation) feeds the site each meter step
  and on every limit change; the site's `nextEvent` arms one timer.
- **scenario DSL:** `site "Depot" { supply 3x400V 250A; transformer 400kVA; fuse "F0" gG 250A { board "MDB" { breaker
  "Q1" C 63A 3p { cable 16mm2 Cu 40m { station "CP-{i}" evse 1 phases L2L3L1 } } load "HVAC" profile "hvac.csv" } } }`
  (final grammar decided by the implementer, canonical in `fmt`); `trip "Q1"`, `reclose "Q1"`, `load "HVAC" set
  20kW`; assertions `expect no trip`, `expect "Q1" current <= 63A`, `expect site imbalance <= 16A`; a run **DLM
  score** (peak utilisation, seconds over limit, A·s over limit, trips, energy delivered, unmet energy vs EV request,
  Jain fairness, phase imbalance) in the report/JUnit.
- **Modbus TCP** (`packages/modbus`): a small Modbus TCP server (function codes 3/4 read, 6/16 write where the map
  allows), one unit id per meter node, register maps SDM630 / EM24 / generic, float32 word order as the real meters,
  values live from the site model; DLM controllers point at `host:502+n`.
- **server/UI:** a **Site** page: single-line diagram of the topology (boards, devices, cables, chargers, loads) with
  live per-phase loading bars, device thermal state, trip/reclose buttons, load step controls; a timeline of
  node currents vs limits; the DLM score. Topology from the DSL or a JSON import.
- **Reference DLM:** a controller (in `packages/grid` or `csms`) that reads the site, computes phase-aware fair
  shares under every node limit, and sends `SetChargingProfile` via the test CSMS; selectable in runs as a baseline.
- **Docs:** a guide "Develop and test a DLM controller" with a worked depot example.

## Order
1. Now (parallel, new packages only): `packages/grid` model + tests; `packages/modbus` server + register maps + tests.
2. After the milestone-4 fixes: core supply integration, DSL + scoring, server/UI Site page + reference DLM, docs.
3. Review, fixes, full check, push.
