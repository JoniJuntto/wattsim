# wattsim milestone 2 implementation plan

> For agentic workers: each task is owned by one subagent. A task names the files it owns; touch nothing else. Tests
> with `bun test`, lint with `bun run lint`, types with `bun run typecheck`, all from the repo root. Commit per task.

**Goal:** wire OCPP 2.1 as a third station version, close the DSL and smart-charging gaps in `docs/backlog.md`.

**Architecture:** 2.1 is a superset of 2.0.1 on the wire for every message the station sends today, so the 2.1
adapter is the 2.0.1 adapter parameterised by version and schema namespace. OCPP-J gains two message types in
2.1 (CALLRESULTERROR 5, SEND 6). Smart charging gets a real composite-schedule evaluator on the virtual clock.
The DSL gains variables as values, direction-aware `expect`, scripted replies to CSMS calls, duration
distributions and more clock/net controls.

**Spec:** `DESIGN.md`, `docs/backlog.md`, `docs/dsl.md` (current syntax), `docs/superpowers/plans/2026-10-29-milestone-1.md` (interfaces).

## Global constraints

- Bun workspaces; Biome (spaces, single quotes, width 120); no new runtime dependencies without a line in
  `DECISIONS.md`.
- Virtual clock only: no `setTimeout`/`Date.now()` outside `WallClock`.
- Every outbound payload must pass `validatePayload` for its version (the Ajv oracle test guards the generator).
- `generated/` is gitignored; run `bun run build` (generator) after touching `packages/protocol/scripts/generate.ts`.
- Strict mode: illegal traffic only via chaos. New DSL syntax goes through parser → formatter → interpreter and
  gets a line in `docs/dsl.md`; `fmt` output must re-parse to the same AST.
- Each task deletes the backlog lines it closes from `docs/backlog.md`.

## Wave 1 (parallel, disjoint packages)

### Task P: OCPP 2.1 wiring — owns `packages/protocol/**`, `packages/core/src/**`, `packages/core/test/**`

Interfaces produced:
- `OcppVersion = 'ocpp1.6' | 'ocpp2.0.1' | 'ocpp2.1'`; `OCPP_VERSIONS` gains `'ocpp2.1'`; `schemaDir('ocpp2.1') === 'v21'`; `isOcppVersion`.
- `generated/v21/index.ts` from `schemas/v21`. Filename rule as v201. `NotifyPeriodicEventStream.json` has no
  suffix: it is the payload of a SEND message; register it as `NotifyPeriodicEventStream.request` with
  `response: z.never()`-equivalent (a schema that rejects everything) and list it in a new export
  `sendActions: readonly string[]`.
- `frame.ts`: `MessageType.CallResultError = 5`, `MessageType.Send = 6`;
  `CallResultErrorFrame = { type: 5; id; code; description; details }`, `SendFrame = { type: 6; action; payload }`
  (SEND is `[6, "<messageId>", "<action>", {payload}]` — 4 elements, same as CALL). Decoding 5/6 is allowed only
  when the caller passes `{ version: 'ocpp2.1' }` as a second argument; for other versions they decode-fail with
  `unknown message type`. `encodeFrame` handles both.
- `errors.ts`: `CALL_ERROR_CODES['ocpp2.1']` = the 2.0.1 list (2.1 kept it). `formatViolationCode` /
  `occurrenceViolationCode` treat 2.1 like 2.0.1.
- `validate.ts` / `actions.ts` / `index.ts`: register v21, export namespace `v21`.
- `packages/core/src/adapters/ocpp21.ts`: `export const ocpp21: VersionAdapter`. Implementation: refactor
  `ocpp201.ts` so its payload builders and `handleCall` are produced by a factory `createOcpp2xAdapter(version)`;
  `ocpp201 = createOcpp2xAdapter('ocpp2.0.1')`, `ocpp21 = createOcpp2xAdapter('ocpp2.1')`. Types stay from
  `v201` (a `satisfies` on a v201 type is still correct for 2.1 because every required field is shared; the
  station21 test proves it against the v21 Zod schemas). 2.1-only inbound actions the station does not implement
  return `null` (NotImplemented) like today.
- `station.ts`: adapter chosen by version (three-way). `connection.ts`: subprotocol is the version string already.
  Inbound CALLRESULTERROR (2.1): treated like CALLERROR for the pending call. Inbound SEND: emit `send` event
  with `{action, payload}` after validation, no reply.
- `test/fake-csms.ts` accepts `ocpp2.1`. New `test/station21.test.ts`: boot, status, full transaction with
  TransactionEvent Started/Updated/Ended, Heartbeat; every frame the FakeCsms received passes
  `validatePayload('ocpp2.1', …)`. Oracle test extends to v21 (Ajv, draft-06/07 whichever `$schema` says).
- `scripts/perf.ts` untouched. README protocol table gains 2.1 (station side). `docs/backlog.md`: delete the
  "2.1 schemas are vendored but not generated or wired" line.

### Task D1: DSL expressiveness — owns `packages/scenario/**`, `packages/cli/**`, `docs/dsl.md`, `examples/**`

Do not touch `packages/core` or `packages/protocol`. If a core API is missing, write the need down in the final
report instead of adding it.

1. **Variables as values.** Any place the grammar takes a number, duration or string literal also accepts a bare
   identifier bound by `let` or a `for` range var (`wait pause`, `repeat n`, `start evse i`, `csms url`,
   `evses n`, `heartbeat hb`, `at +d`, `clock speed s`). AST: introduce `NumExpr = {kind:'number'} | {kind:'ref'}`,
   `DurExpr = {kind:'duration'} | {kind:'ref'}` and use them in the statement nodes; the interpreter resolves refs at
   run time and fails with the statement's `loc` when the bound value has the wrong type. Formatter prints the
   identifier. Also `version 2.1` is accepted (`OcppVersion` in `ast.ts` gains `'2.1'`; maps to `'ocpp2.1'` — the
   core accepts the string once Task P lands; write the interpreter mapping now, it is a plain string).
2. **`expect` direction.** `expect call <Action> [payload] [within d]` matches an outgoing CALL,
   `expect result <Action> [payload] [within d]` the CSMS CALLRESULT to one, `expect error <Action> [code]` a
   CALLERROR to one. Bare `expect <Action>` keeps today's behaviour (either, by shape). Formatter emits the
   keyword when present.
3. **Scripted replies.** Station-block statement `on <Action> [payload-pattern] { reply <json> }` and
   `on <Action> { error <Code> "<description>" }` installs a handler that answers the next matching inbound CSMS
   CALL instead of the station's built-in handler; `on ... always { ... }` keeps it installed. This needs a core
   hook: use `Station.on('call', …)`-style interception if it exists; if it does not, implement the handler as a
   `Connection` middleware if the scenario package can reach it, otherwise report the exact core API you need
   (signature, where) and leave the parser + formatter + docs in place with the interpreter raising
   "not supported yet" with the `loc`.
4. **`send` payload optional.** `send Heartbeat` = `send Heartbeat {}`.
5. **Distributions.** `choose` weights accept decimals; durations accept `normal(45min, 10min)`, `uniform(1s, 5s)`,
   `exp(30s)` anywhere a duration is taken, sampled from the run's seeded RNG (`fnv1a` of seed + station + statement
   loc, as `choose` does today) so a run is reproducible for a given `--seed`. Formatter prints the call form.
6. **Clock & net.** `clock set "2026-03-29T01:59:50Z"`, `clock freeze` / `clock resume`, negative `clock drift`,
   `net delay 200ms [for 10s]` (per-frame latency via the existing `ChaosEngine` delay rule, both directions),
   `net drop` unchanged, `at -5s` is still an error (document why in `docs/dsl.md`).
7. Formatter keeps comments: attach leading `//` comments to the next statement and trailing ones to the same
   line; `fmt` round-trips `examples/*.ws`. `60s` canonicalizes to `60s` (only exact unit multiples collapse:
   `120s` → `2min`, `90s` stays).
8. Every change: parser test (good + precise error), formatter round-trip test, interpreter test against the
   existing FakeCsms (import from `@wattsim/core/test/fake-csms` as today's tests do). Update `docs/dsl.md` and
   the examples where a new form reads better. Delete closed lines from `docs/backlog.md`.

## Wave 2 (after wave 1 is committed; parallel, disjoint)

### Task S: Smart charging — owns `packages/core/src/charging.ts` (new), `station.ts` (limit code only), `adapters/ocpp16.ts`, `adapters/ocpp201.ts` (SetChargingProfile / ClearChargingProfile / GetCompositeSchedule / GetChargingProfiles / ReportChargingProfiles only), `test/charging.test.ts`

- `charging.ts`: `ProfileStore` holding installed profiles per EVSE (0 = station). `limitAt(evseId, t: number): number | undefined`
  resolves stackLevel (highest wins within a purpose), purpose precedence
  (`ChargingStationExternalConstraints` < `ChargingStationMaxProfile`/`ChargePointMaxProfile` < `TxDefaultProfile` < `TxProfile`
  as the spec's "most specific" rule: Tx > TxDefault, both capped by Max and ExternalConstraints), `validFrom`/`validTo`,
  `startSchedule` + `duration`, every `chargingSchedulePeriod` (step function), `Recurring` Daily/Weekly, unit W or A
  (A → kW via `cfg` voltage × phases, as `scheduleLimitKw` does now). A station-level profile (evseId/connectorId 0)
  is a shared cap divided across EVSEs with an active transaction at `t` (equal split; document in `DECISIONS.md`).
- `composite(evseId, from, durationMs, unit)` returns the 1.6 / 2.0.1 `GetCompositeSchedule` response periods.
- `clear(criteria)` returns how many were removed; adapters answer `Unknown` when 0.
- `Station`: `setLimitKw` is replaced by the store; the meter sample uses `limitAt(evse, clock.now())`; a limit
  change re-samples and (2.0.1) emits `TransactionEvent Updated` with `ChargingRateChanged` only when the
  effective limit actually changed. `TxProfile` entries die with their transaction (existing behaviour).
- Backlog: delete all four smart-charging lines.

### Task T: 1.6 violation codes — owns `packages/protocol/src/validate.ts`, `errors.ts`, `packages/core/src/connection.ts` (inbound-validation reply only), tests

- `Violation` gains `code: 'format' | 'property' | 'type' | 'occurrence'` derived from the Zod issue
  (`invalid_type` on a missing required → occurrence; wrong primitive type → type; enum/pattern/min/max → property;
  unparseable → format). Connection's CALLERROR for an invalid inbound CALL picks
  `FormationViolation`/`PropertyConstraintViolation`/`TypeConstraintViolation`/`OccurenceConstraintViolation` for
  1.6 and the 2.x spellings otherwise (first violation wins). Delete the backlog line.

### Task D2: DSL leftovers — owns `packages/scenario/**`, `docs/dsl.md`

- Whatever D1 reported as left over, plus: a chaos rule may take several triggers (`chaos drop out MeterValues nth 3 once`
  already; add `every 2 from 5`), station template names are checked for a `{var}` reference when a `for` range exists,
  `fmt --check` exit code 1 on unformatted input (CLI).
